# GitHub reference apply adapter — internal staging

**Status:** Internal implementation [#189](https://github.com/attention-spa/gh-plan/issues/189). Not published, not an implicit GitHub writer, not an exported public \`applyPlan()\` call, and **not an authorization to change production GitHub resources**.

The separately selected, internal factory \`createGithubReferenceApplyOptions(config)\` in \`src/github-reference-adapter.ts\` produces the previously approved C2 \`ApplyPlanOptions\` callback contract. The caller must deliberately invoke the internal #188 lifecycle, supply a fully validated desired-state plan, a runtime bearer credential, and an asynchronous **durable** audit sink. The factory validates whole-plan B1 preflight before any network interaction. Callers must create **a fresh adapter instance for each run**; uncertain acquisition or write cannot be retried or used to initialize a new run without independent reconciliation.

## Trust, authorization and scope

The reference adapter composes:

- **A1 ownership:** \`acquireGithubCasLock()\` and the authenticated REST+GraphQL backend. Exact canonical repository, default branch and tree, unique off-ref owner commit, zero-OID non-force \`updateRefs\` acquisition, independent owner ref/commit readback, ownership recheck before each mutation and matching-owner conditional release. No TTL, automatic stale-owner deletion, ref-force bypass or cross-process fencing of noncooperating clients.
- **B1 milestone and issue readers:** the existing independently tested GET-only \`createRestMilestonePostconditionReader()\` and \`createRestIssuePostconditionReader()\`. Reads check versioned typed predicates, unique identity, *all* paginated open/closed catalog pages (excluding PRs), and the independent by-number resource before/after each write; updates preserve omitted fields. The C2 lifecycle handles late-bound producer identities, verified replays and sanitized audit/error handling.
- **Reference transport:** \`createGithubReferenceHttp()\` is *internal*, binds every request to \`https://api.github.com\` and the exact repository, uses \`X-GitHub-Api-Version: 2026-03-10\`, \`Accept: application/vnd.github+json\`, runtime bearer and \`redirect:error\`. GETs are restricted to repository metadata, exact refs/commits, and issue/milestone catalog/detail. Mutations are restricted to one off-ref A1 commit, exact A1 \`updateRefs\` GraphQL with \`force:false\`, and the four B1 \`POST/PATCH\` issue/milestone endpoint/body shapes. The final REST dispatcher matches requests to the *same* frozen preflight step and precisely bound late references; never accepts arbitrary host, URL, GraphQL query, injected label/assignee field or unchecked callback as evidence of safety.
- **Audit:** a durable caller-provided \`onLog\` sink is **mandatory** for the reference factory. The #188 lifecycle awaits each immutable \`(runId, sequence)\` entry before dispatch. A sink failure stops all later writes; failures after a possible write may retain the lock pending manual recovery. A callback or sink can lie: no package-side check guarantees external storage durability or operational human authorization.

The internal factory does not export a new source-level public API. \`src/index.ts\` remains unchanged, \`planGithub()\` is read-only, and \`applyPlan()\` stays unavailable until [#190](https://github.com/attention-spa/gh-plan/issues/190). A caller may still supply arbitrary callbacks through the **generic** future C2 API; the mere fact that they type-check cannot establish they use this trusted adapter. Never label arbitrary callback execution as authenticated GitHub reconciliation.

## Token requirements and private repository permissions

Prefer a **short-lived GitHub App installation token** scoped only to the selected repository. Minimum intended capability is **Metadata:read**, **Contents:read/write** (inspect Git refs/commits; create off-ref commit; CAS-update exact lock ref), and **Issues:read/write** (open/closed issues/milestones, issue and milestone POST/PATCH). Setting the milestone on **new issue creation** additionally requires GitHub's **push access**; the adapter checks the target repository's returned \`permissions.push === true\` whenever such a create occurs. A false/unavailable push capability fails closed. Real GitHub permissions can differ by actor, token class, branch rulesets, and organization policy; no generic permission-scopes assertion substitutes for an actual authenticated target-repository check. Protected-ref/ruleset denial is never bypassed. No token is embedded in source, plans, error causes, logs or output.

GitHub may return **404 for an inaccessible private repository**. A 404 for a repository or issue/milestone detail is not treated as an empty catalog or absent resource. The only expected 404 is for the A1 **exact lock ref**, and it is accepted only following prior canonical-repository validation plus an independent fresh repository identity GET under the same token. Unauthorized/hidden 404 otherwise fails closed. Runtime credentials must not be printed, persisted in plans, or reused after expiry.

## Pacing and retry policy

All GETs, Git commit POSTs, GraphQL CAS mutations, and issue/milestone POST/PATCH use one serialized FIFO. **Every pair of mutative requests is spaced by at least 1,000 ms** (including the A1 ref creation and release requests). No GET or write is sent to an unapproved origin; redirects are never followed.

Only GETs can retry, with **at most two extra attempts** and **at most 30 seconds per accepted delay**. \`Retry-After\` takes priority, then an exhausted primary limit's \`x-ratelimit-reset\`. If the retry budget is exceeded, or a secondary limit lacks an acceptable bounded reset (GitHub recommends at least one minute), the adapter stops instead of hammering GitHub. An ordinary 403 is a permission denial, not a rate-limit retry. A mutation returning 403/429/422, transport loss, malformed response or redirected write is **uncertain**: **never** blindly reissue POST/PATCH. Instead, keep ownership when effects may be unknown, reread independently, and require operator reconciliation if proof is unavailable. This is intentionally more conservative than optimizing throughput.

## Identities, replay and cancellation

Issue.create uses an exact unique body marker, milestone.create an exact unique title; both require a fresh full catalog and by-number GET before treating an existing resource as satisfied. Issue/milestone updates use the exact numeric path; create responses must match independently verified REST number, ID and \`node_id\`. The factory rejects any mutation callback request not matching the frozen step's method, path, body, repository and current verified late-bound bindings. A failed write never retries even when the outgoing HTTP reply is lost. The #188 core can only skip verified terminal state, recording partial verified/skipped IDs.

An issue create followed by a planned dependent close is a special replay case. The original B1 reader **correctly requires initial \`state=open\`**; the adapter does **not** weaken that reader. For the second, explicitly superseding \`closed\` check, it independently rereads the exact issue marker through a complete GET catalog and a fresh by-number GET and verifies all other original create fields, the final closed state and full REST identity. Every other mismatched marker/title is an error, never adoption.

The caller's AbortSignal stops new writes, but an in-flight GitHub write might still commit after local cancellation. The adapter deliberately keeps the transport available for terminal readback and a safe conditional release; it does **not** abort the underlying A1 token/ref transport and pretend the remote operation stopped. Missing postcondition evidence or an uncertain callback retains ownership for separate [#176](https://github.com/attention-spa/gh-plan/issues/176) manual recovery with human approval.

## Verification record and limitations

- **Deterministic full-stack fake transport:** \`tests/github-reference.test.ts\` runs the internal #188 lifecycle against the actual A1 CAS and B1 readers using a serial GitHub REST/GraphQL fixture. It tests the mixed five-step/four-kind graph, issue create→close zero-write replay, all A1 mutations at >=1s spacing, token/version/redirect/URL allowlisting, 403 vs private 404, push-access refusal, multi-page catalog reads and PR exclusion, GET retries for \`Retry-After\`/primary reset, rate-limit refusal on writes, concurrent owner rejection, unknown POST lock retention, audit refusal, and non-B1 field/GraphQL rejection.
- **Real private disposable REST/GraphQL API smoke:** [permanent #189 evidence](https://github.com/attention-spa/gh-plan/issues/189#issuecomment-6932575261). Used a new private test repo and agent-hachi administrator token, not a least-privilege App token. Confirmed A1 exact-ref zero-OID/matching-OID CAS with independent ref GET, off-ref unchanged default tree, milestone create (201), issue create with milestone assignment (201, push access), issue update (200), milestone update (200), authoritative by-number and full open/closed catalog GETs. Test repository **deleted (HTTP 204; later GET 404)**. These calls tested the live GitHub API **directly**, not live execution of the TypeScript adapter. The direct REST connector did not expose an API-version header override, so pinned-version assertion is proven by the fake transport fixtures only.
- **Due-date discrepancy:** the live milestone POST supplied \`2027-01-03T00:00:00Z\`, but the 201 response and fresh GETs returned **\`2027-01-02T00:00:00Z\`**. This is **not** a passing B1 due-day postcondition and must never be silently shifted. Deterministic tests assert the reference executor stops and retains ownership on this drift. [#181](https://github.com/attention-spa/gh-plan/issues/181) is still required to investigate date semantics and prove all four kinds **with the actual adapter on a disposable private GitHub repository**, before any public executor export.

No production repository token grant, resource mutation, tag, npm publication or workflow configuration was changed in #189. This separate adapter is not an independent authorization to run a plan.
