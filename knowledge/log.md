The entire plan must pass metadata, repository, request method/path/body, managed-property coverage, marker/title/numeric identity, DAG and late-ref checks before any callback or lock; unresolved noops fail closed until fresh under-lock readers are implemented. Added deterministic rejection/mixed-DAG fixtures and integrated them into `npm test`. This **does not implement GitHub writes, a lock, postcondition readers or the public `applyPlan()` export**; the C2 caller-trust limitation and separate implementation gates remain in place.

- **M8.1.6c owner-selected public callback API ([#166](https://github.com/attention-spa/gh-plan/issues/166), [PR #191](https://github.com/attention-spa/gh-plan/pull/191))**: Accepted C2 instead of the previously recommended C1: future optional public `applyPlan()` accepts caller-supplied dispatch, postcondition/catalog readers and ownership callbacks, with an explicit trust acknowledgement. The package cannot authenticate callback behavior, verify that GitHub GETs occurred or guarantee cooperative locking, so a separate GitHub reference adapter and disposable-private-repository evidence remain prerequisites for any live safety claim. Recorded typed options/results/errors, sanitized audit and abort/failure semantics, permission and transport policy and the continued private-package/read-only boundary; registered four blocked implementation leaves ([#187](https://github.com/attention-spa/gh-plan/issues/187)–[#190](https://github.com/attention-spa/gh-plan/issues/190)). A1 CAS and B1 four-kind strict preflight are preserved; no runtime code/public export or production mutation in this architecture-only decision.

- **M8.1.6a cooperative ownership architecture ([#164](https://github.com/attention-spa/gh-plan/issues/164))**: Selected the GitHub-native `updateRefs.beforeOid` CAS design (A1) for direct and Actions callers, with one repository-wide ref, a unique off-ref owner commit, exclusive conditional acquisition/release, owner rechecks before each mutation and fail-closed unknown outcomes. No TTL, automated reaper or stale-lock steal; manual recovery requires independent proof that the old owner and in-flight GitHub writes have stopped. The policy explicitly **does not** promise global exactly-once execution or atomic fencing of GitHub Issues REST. Created two blocked, independently verifiable implementation leaves: [#175](https://github.com/attention-spa/gh-plan/issues/175) CAS lock primitive and disposable-repo tests, followed by [#176](https://github.com/attention-spa/gh-plan/issues/176) manual recovery runbook. Public execution remains unexported and blocked by [#163](https://github.com/attention-spa/gh-plan/issues/163).

- **M8.1.5 repeat-run and interrupted-create integration fixtures ([#131](https://github.com/attention-spa/gh-plan/issues/131), [PR #162](https://github.com/attention-spa/gh-plan/pull/162))**: Added a stateful fake GitHub integration fixture testing a complete late-bound milestone/create/update DAG, a second run of the exact same plan with zero writes, and recovery from two mid-run failures (lost create response after remote commit and failed post-write verification).
