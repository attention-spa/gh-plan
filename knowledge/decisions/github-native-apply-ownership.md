## Summary

**Architecture decision A1, accepted in [#164](https://github.com/attention-spa/gh-plan/issues/164):** future direct and Actions callers of the optional public `applyPlan()` must cooperate through a GitHub-native, per-target-repository **exclusive ref ownership** protocol. No external lease database, GitHub Actions-only restriction or automatic stale-lock takeover is required for the first version. This was approved as a design and is now **implemented internally** as a CAS primitive under [#175](https://github.com/attention-spa/gh-plan/issues/175); it is **not** a public executor. Manual abandoned-lock recovery is now separately implemented **internally** under [#176](https://github.com/attention-spa/gh-plan/issues/176) with an [operator runbook](../../docs/operator-cas-recovery.md), exact-OID approval gate, fail-closed CAS deletion and audited refusal tests; it is never automatic. The [architecture gate](https://github.com/attention-spa/gh-plan/issues/163) is completed.

## Decision and scope

- **One lock per target repository**, regardless of logical namespace or which issues are managed. The single canonical branch ref is `refs/heads/gh-plan/locks/repository`. All cooperating writers, including local callers, agents and GitHub Actions, must use it. Resolve canonical repository identity and enforce target-repository equality before accessing the lock.
- **Owner identity is a unique Git commit object OID**, not just a reusable branch head SHA. Before acquisition, construct an off-ref Git commit using the current default-branch tree and parent commit, with no file changes. Its nonsecret message embeds a newly generated random run nonce and opaque owner/run ID. Create the commit object via `POST /repos/{owner}/{repo}/git/commits`; it does not move any branch. The resulting unique 40-hex commit SHA must be checked against the commit message/owner record before use. The exact nonce format and metadata parser are implementation details covered by contract tests.
- **Exclusive acquire:** send a single GraphQL `updateRefs(input:{ repositoryId, refUpdates:[{name:"refs/heads/gh-plan/locks/repository", beforeOid:ZERO, afterOid:OWNER_OID, force:false}] })`, where `ZERO` is exactly 40 zeroes. A successful CAS writes the ref only if no such ref existed. Perform an independent authenticated exact-ref GET and verify the observed commit OID and owner marker before allowing any GitHub resource mutation. If CAS fails, has an unknown transport outcome or the read is ambiguous, **stop**. After a lost CAS response, only an exact owner-identity read can establish acquisition; never blindly retry the mutation.
- **Ownership invariant:** before **each** mutating resource request, independently re-read the full ref (use the exact `GET /git/ref/heads/gh-plan/locks/repository` path and require exact `ref` value, not a prefix-matching list), its type and commit OID. Compare against the acquired owner OID and local execution context. Mismatch, absence, permission failure or unclear result halts execution without dispatching another write. Disallow concurrent mutations **within one owner**; at most one in-flight GitHub resource mutation per owner.
- **Exclusive release:** only after all in-flight operations have terminally resolved and post-write verification/audit is completed, reread exact ownership and GraphQL-CAS `beforeOid:OWNER_OID`, `afterOid:ZERO`, `force:false`. Read back the ref state. Do **not** use unconditional REST ref deletion; never release another owner's lock. If the release response is uncertain or the ref changed, stop and require investigation rather than claiming success.
- **Credentials:** lock needs target-repository Git objects/ref read and write access, typically `Contents:read/write` for fine-grained app tokens. Validate actual GraphQL permission behavior, ref namespace and branch/ruleset restrictions on an isolated disposable repository before enabling. It is distinct from the `Issues` permissions for executing planned work. All auth stays runtime-only; plans/logs never contain it.

## #175 internal implementation and disposable-repository proof (2026-11-16)

The internal `src/github-cas-lock.ts` provides a repository-identity-validated owner primitive and runtime-authenticated GitHub REST/GraphQL backend. It creates a unique off-ref commit (unchanged default branch tree, default head parent, random UUID nonce, nonsecret run/repository identity), acquires the exact ref with atomic GraphQL `beforeOid=ZERO`, and independently reads the exact ref and owner commit before accepting ownership. The mutation guard serializes resource writes and rereads the exact owner before every operation; an unknown/throwing mutation retains ownership and prohibits release. Release uses matching-OID GraphQL CAS `afterOid=ZERO`, `force:false`, and exact-ref absence readback. Unknown mutation results are **never** blindly retried. A lost acquire reply can be reconciled only by positive exact owner readback; a lost release reply is always treated as uncertain.

**Real GitHub proof on a dedicated disposable private repository** `agent-hachi/gh-plan-cas-175-20261116` (REST ID `1460429407`, GraphQL ID `R_kgDOVwxiXw`), distinct from all production repositories:

- The test repo's default `main` OID was `509c26e8e6acc017d412b3191cfd315586ff0422`; unchanged tree `d8c794d4c3354542b996361a38a6b9e1d6461985` was reused for separately created off-ref owner commits A `fdd4f3431524cd6d75fc0310680c16781216471d` and B `b9b36cb5d08f54a296706a3cdd171aca0a92e292`, each with distinct opaque run/nonce metadata.
- A successfully acquired `refs/heads/gh-plan/locks/repository` with GraphQL `updateRefs`, `beforeOid=0000000000000000000000000000000000000000`, `afterOid=A`, `force:false`. An independent exact-ref GET and owner-commit GET matched A.
- While A owned the ref, B's zero-OID acquire and B's owner-mismatched release were rejected. Both GraphQL mutation attempts returned **HTTP 200 with `errors`, no `data`**, not a successful CAS. Exact-ref readback confirmed A remained the owner. A's matching-OID conditional release succeeded, and the exact ref returned 404.
- B then acquired from ZERO. Old owner A's conditional release was rejected while exact-ref readback still showed B. B subsequently released with its own exact OID. No production issue or branch was changed.

**Permission/protection limitations:** this live private-repo test used the agent-hachi **administrator** credential, establishing effective write access rather than proving least-privilege authorization. GitHub's documented minimum for a trusted reference adapter is repository Metadata:read plus **Contents:read/write** to inspect refs and create Git objects/update refs; separate Issues:write is needed for later B1 resource dispatch, not the lock. On this account, reading the private test repository's rulesets and branch protection endpoints returned 403 with GitHub's upgrade/private-plan restriction. Real protected-ref behavior therefore **was not tested**. Permission/protection denials, wrong target identity and GraphQL errors are fail-closed in synthetic tests; the implementation must never bypass an organization's rulesets. The disposable repository is removed after the integration check. No GitHub App token scopes or production permission settings were changed.

**Scope and guarantees:** the CAS primitive is internal (not exported from `src/index.ts`), has no TTL, fencing token, automatic lease renewal, stale-owner steal or background reaper. External/non-cooperating clients can still write GitHub issues; the GitHub Issues REST write and preceding lock read are not atomic. In-flight unknown results retain the lock, and all abandoned-lock recovery remains a separate, separately authorized task [#176](https://github.com/attention-spa/gh-plan/issues/176). The C2 public facade and production reference adapter are not enabled by this unit.

## Crash and abandoned-lock recovery

There is **no TTL, heartbeat-based steal, clock-based expiry, automatic ref deletion or unattended reaper** in v1. A crashed owner leaves its ref intact, intentionally making other runs refuse to write. The owner may release the lock normally only if it still controls the exact ref and has no unresolved in-flight mutation. A lost process cannot implicitly authorize a successor.

An operator may authorize a *manual*, fully audited abandoned-lock clearance **only** after independently establishing that the old process is terminated and **all its in-flight GitHub writes** have ended. Read the owner commit/ref and the affected resource state, record proof of stop and the exact OID, request separate human authorization, then CAS-delete the ref with `beforeOid` equal to the observed abandoned owner OID and `afterOid:ZERO`. Abort on changed ownership or uncertain API response. Merely seeing an old timestamp, completed GitHub Actions run or idle runner is **not** sufficient proof. Unlocking neither reruns nor resumes a plan. The next caller must acquire with a fresh owner OID and perform independent plan preflight and postcondition reads.

The audited [operator recovery runbook](../../docs/operator-cas-recovery.md), internal recovery helper and disposable-repository tests are implemented under [#176](https://github.com/attention-spa/gh-plan/issues/176), after the independently merged #175 primitive. This does not authorize clearing any real production lock.

## #176 operator-only recovery implementation (2026-11-16)

The internal `src/github-cas-recovery.ts` implements a **manual-only** abandoned-owner inspection and CAS cleanup gate. The [runbook](../../docs/operator-cas-recovery.md) provides a PowerShell 7 procedure for an authorized operator. The helper requires a bound recovery dossier with process+worker stop attestations, definitive termination of **all** network requests, independent resolution of potentially affected GitHub resource writes, durable incident/proof links, and a **separate human exact-repository/owner-OID approval**. It validates the repository's REST ID/node ID, the canonical exact ref, complete owner commit message/nonce/base commit and unchanged tree, then rereads the owner again before attempting a single GraphQL CAS `beforeOid=verifiedOwner`, `afterOid=ZERO`, `force:false`. An approved attempt must be durably audited **before** deletion; success requires verified exact-ref absence, a final canonical repository identity check, and durable completion audit. Callback-supplied attestations and audit persistence are caller-trusted, **not cryptographically proven**, so a human must independently inspect the evidence and approver identity. No API can establish that an external owner or REST request has actually stopped.

**Live disposable private-repository proof:** [#176 test evidence](https://github.com/attention-spa/gh-plan/issues/176#issuecomment-6927746014) records a fresh private repo, unchanged-tree owner commit, simulated abandoned lock, a rejected wrong-owner `updateRefs` CAS (`data.updateRefs:null` and GraphQL errors despite HTTP 200) while exact ref remained unchanged, followed by an explicitly test-only matching-owner CAS delete and independent 404 exact-ref readback. The fixture approval was posted by the test actor under the owner's authorization of **disposable testing**, not a human production-lock approval. The private repository was deleted after copying its minimal evidence into #176, and deletion was confirmed by 404. No production lock/ref/resource state was touched.

Deterministic failure-injection tests cover crash before/after acquisition; idle-but-alive owner, other workers and in-flight REST call refusing recovery; stale/mismatched ref/OID, forged owner metadata/tree, wrong repo identity, denied scope, cancellation, approval evidence errors, audit failures, CAS racing ownership replacement, network response loss before/after CAS, and failure of post-delete ref/repository reads. No TTL, lease expiry, force overwrite, auto-reclaimer, public apply API, or implicit plan replay exists. Recovering an abandoned lock **does not establish exactly-once execution**; the next writer must independently acquire a **new** owner and reread desired state and postconditions.

## Guarantees, limits and alternatives

- GitHub [`updateRefs`](https://docs.github.com/en/graphql/reference/git#updaterefs) documents atomic updates with `beforeOid`; zero verifies nonexistence, and zero as `afterOid` deletes a ref. This establishes an **atomic cooperative acquisition/release claim**, not a transaction covering GitHub Issues/PR/Projects REST writes. The current live GraphQL schema exposes `updateRefs` and `RefUpdate.beforeOid`, and **live disposable-repository CAS/contender tests were subsequently performed for #175**, as recorded below.
- Cooperative exclusion requires **every participating writer** to honor the lock and requires operators not to reclaim it while any old mutation can still complete. GitHub Issues mutations do **not** accept a corresponding lock fencing token. A resource write could be accepted after a last ownership GET if a privileged external actor removes the ref in that interval. Malicious/uncooperative actors, force ref changes, GitHub eventual consistency, process crashes and API failures prevent a **global at-most-once or exactly-once guarantee**. The internal marker-based create recovery and authoritative postconditions remain necessary.
- Do not treat the lock branch as ordinary feature work: auto-delete-merged-branches or bulk cleanup must never delete `refs/heads/gh-plan/locks/repository`. A ref with this name may be subject to organization/repository rulesets; a lock denied by protection policy is a hard blocker, not a reason to bypass branch protections. Never operate on a production repository to validate CAS behavior.
- External linearizable leases (A2) add a storage service and independent fencing complexity without GitHub REST support for fence checks. Actions `concurrency` (A3) only coordinates participating workflow runs, not direct library callers. Marker-only optimistic reads have no atomic exclusivity and are rejected.

Validate successful and contested recovery only on a disposable repository.

Neither leaf authorizes implementation by itself. The broader [#163](https://github.com/attention-spa/gh-plan/issues/163) public-execution gate, including machine-verifiable postcondition coverage and the owner-approved [C2 caller-injected public API](/decisions/caller-injected-apply-contract.md), remains open pending documentation reconciliation. The generic C2 facade **cannot independently verify that arbitrary owner callbacks implement A1**; the reference GitHub adapter must enforce this policy. No new exported `applyPlan()` or runtime writer is added by this decision.
